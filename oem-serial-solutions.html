// What can be evaluated

More than a one-off adapter.

Because the bridge firmware is under Crux Resolve control, a deployment can be evaluated around the behavior your application actually needs rather than forcing every use case into one fixed configuration.

Serial defaults

Application-specific baud rate, parity, stop-bit, framing, timeout, or connection defaults can be evaluated when the hardware supports the required interface.

Network behavior

Projects can be evaluated for deployment-specific WiFi naming, credentials, local addressing, TCP behavior, reconnect logic, keepalive behavior, and similar firmware-controlled functions.

Application-specific firmware

Where a transparent bridge needs additional connection management, status behavior, diagnostics, or a constrained workflow, Crux Resolve can evaluate a custom firmware path.

Repeatable deployments

For multiple units used with the same equipment, the goal can shift from manual setup to a known, repeatable configuration that reduces field setup and support burden.

Integration review

Crux Resolve can review serial pinout, electrical requirements, host software, cabling, timing, and network expectations before recommending whether the current GB-01 hardware is a reasonable platform.

Future hardware requirements

If a project requires signals the current GB-01 does not expose—such as RTS/CTS or a different physical interface—the requirement can be separated from firmware work and evaluated as a hardware-revision need.

// Current GB-01 hardware boundary

Know what firmware can—and cannot—change.

Firmware-controlled

  • Connection logic and session behavior.
  • Supported serial configuration choices within the ESP32/UART capabilities.
  • WiFi and TCP behavior implemented in firmware.
  • Device identification, status, diagnostics, and application-specific defaults.
  • Transparent transport behavior and reconnect handling.

Hardware-controlled

  • Current production GB-01 is a standard 3-wire RS232 interface.
  • DB9 pin 2 RX, pin 3 TX, pin 5 GND.
  • RTS/CTS and other modem-control lines are not routed on current hardware.
  • USB-C provides bridge power.
  • Different electrical interfaces or additional physical signals can require a future board revision rather than firmware alone.
Scope is application-dependent: custom firmware or OEM work is evaluated case by case. This page describes areas Crux Resolve can evaluate; it is not a promise that every requested behavior can be implemented on the existing GB-01 hardware.
