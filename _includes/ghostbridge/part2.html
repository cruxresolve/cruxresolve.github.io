// What it does

A transparent local bridge.

GhostBridge relays bytes between a local TCP connection and its RS232 interface without interpreting the application protocol. GhostTune with the published MicroSquirt configuration is the verified production use; other RS232 applications may also be compatible when their electrical, cabling, serial, and client-software requirements match the bridge.

🔌 Assembled hardware

The bridge arrives assembled with a DB9 RS232 interface and USB-C power input. Join its WiFi network and connect through the published local TCP endpoint.

📡 Its own WiFi network

No router or internet connection is required. A phone, tablet, computer, or other compatible TCP client can connect directly to the bridge’s local access point.

✅ Optimized for GhostTune

GhostBridge is designed and verified around GhostTune’s MicroSquirt workflow, providing a known hardware path for the supported ECU profile.

↔️ Not software-locked

The byte-relay design is not restricted to GhostTune. Other RS232 and TCP applications may work when the complete serial and electrical setup is compatible; they are not represented as verified unless Crux Resolve explicitly lists them.

🔐 Local communication

Serial traffic stays on the direct local connection. GhostBridge does not provide a cloud relay or remote logging service.

🧰 Rev 12 enclosure

The production enclosure uses a 3 mm main wall, reinforced connector closures, four M3 screw rails, internal ribs, rubber-foot recesses, and debossed branding.

// Next generation

GhostBridge v2.0 (GB-02) is in development.

GhostBridge v1.0 (GB-01) is the currently available RS232-to-WiFi bridge. GhostBridge v2.0 (GB-02) is being developed as a broader WiFi interface platform designed to move beyond RS232-only operation while remaining independent of any one ECU or client application.

Planned GB-02 v1 transport targets

  • WiFi to RS-232.
  • WiFi to TTL UART.
  • WiFi to RS-485.
  • WiFi to CAN / CAN-FD.
  • WiFi to USB Serial / Host.
  • Universal I/O breakout-harness architecture for transport-specific connections.

Development status: these are planned GB-02 v1 targets, not claims of currently shipping or fully validated support. Each interface will be represented as supported only after its hardware, firmware, electrical, and transport behavior has been qualified.

Transport is not protocol: GhostBridge is intended to move bytes and frames between WiFi clients and supported wired interfaces. ECU, device, or application-specific meaning remains with the client software rather than being hard-coded into the bridge.
// GhostTune setup

Three steps.

Connect and power

Connect the DB9 interface to the supported ECU serial connection and power GhostBridge through USB-C.

Join the bridge network

In the iPhone or iPad WiFi settings, select the network named GhostBridge-XXXXX. The password is 1234 followed by the last four characters of that WiFi name. Example: GhostBridge-ABCDE uses password 1234BCDE. Each GhostBridge uses device-specific credentials so nearby units do not share the same password.

Open GhostTune

GhostTune connects to 192.168.4.1 on TCP port 35000 and verifies the supported ECU profile.

Using other serial software? The host application must be able to communicate through the bridge’s local TCP endpoint, and the connected hardware, cabling, electrical interface, and serial configuration must be compatible. Crux Resolve only represents configurations as verified when they are explicitly listed.
