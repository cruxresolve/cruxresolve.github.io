What GhostTune verifies during live-ECU testing

GhostTune is in final live-ECU testing. That means comparing the application’s behavior with real hardware and established tuning workflows—not only confirming that screens open or simulated data looks correct.

Current status: Public release timing has not been announced. Testing is focused on the current configuration using MicroSquirt hardware running MS2/Extra 3.4.4 through a local WiFi-to-RS232 connection.

Why real-hardware testing matters

An ECU tuning application has to interpret live values correctly, preserve tune data, handle communication interruptions, and keep unsupported operations blocked. A feature that behaves correctly in Demo Mode still needs to be checked against an actual ECU before it can be represented as ready for use.

What the current test process covers

  • Connection and identification: confirming that GhostTune reaches the local bridge, receives valid ECU responses, and selects only the matching profile.
  • Live-data comparison: comparing RPM, MAP, AFR, coolant temperature, battery voltage, and other supported values with an established reference workflow.
  • Backups before changes: confirming that a known-good tune can be saved before any live write test begins.
  • Temporary and permanent changes: checking that temporary writes and permanent burns remain distinct and follow the guarded sequence shown to the user.
  • Read-back verification: re-reading changed data and reporting mismatches instead of assuming that a write succeeded.
  • Alerts and invalid states: checking that warnings appear only when the engine state and sensor data make the warning meaningful.
  • Interruptions and recovery: testing reconnect, stale-data handling, and recovery guidance when communication does not complete normally.

Compatibility is intentionally narrow

The current test target does not establish compatibility with every ECU or every firmware version. GhostTune keeps other profiles and write paths blocked until their addresses, scales, communication behavior, writes, burns, and recovery behavior can be validated independently.

Third-party product and project names on this site identify the hardware and firmware used for compatibility testing. GhostTune is an independent Crux Resolve LLC product and is not affiliated with, endorsed by, or sponsored by the owners or developers of those products or projects.

Follow the testing process

The GhostTune product page includes an optional form for release updates and limited-testing interest. Owners can include their ECU hardware and firmware version so future compatibility work can be prioritized using real configurations rather than guesses.
